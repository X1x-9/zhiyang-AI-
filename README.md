# 智养AI - AI健康管理平台

## 🎨 项目简介

智养AI 是一个基于 Next.js 16 的全栈健康管理应用，围绕「记录 → 计划 → 执行 → 复盘 → 调整」组织日常饮食、训练与体重管理。用户记录餐食、训练和体重，系统按资料生成饮食与训练计划，执行结果回到复盘，出现显著偏差时触发调整。

营养目标、餐次区间、训练排程与偏差阈值由规则引擎计算，模型负责理解输入、组织建议与对话，不能改写计算结果。两类输出合并为计划版本，每次生成与调整都有记录。

系统提供一般健康信息与生活建议，不做疾病诊断，不替代医生处方；缺少记录时保持空白或明确说明，不用推测数据填充图表和结论。

公网版本已部署在阿里云 ECS：http://116.62.42.146:3100。演示账号：3359786126@qq.com，密码：11111111。该账号仅用于功能体验，请勿填写真实健康数据。

### ✨ 项目亮点

- **确定性引擎 + 受约束 Agent**：计划目标与排程由规则引擎完成，Agent 只能调用 6 个白名单工具补充建议。
- **混合检索与引用**：向量 + BM25 双路召回，重排后带片段序号与来源回链。
- **多模态餐食识别**：视觉模型识别菜品与份量，结构化模型输出营养 JSON，用户确认后入库。
- **动态调整**：热量超过确定性阈值时生成临时调整，确认后生效，可撤销。
- **MCP 工具链**：知识检索、营养估算、安全核对、天气查询 4 个工具。
- **流式输出安全**：SSE 流按句校验，四类医疗越界内容替换为保守表述。
- **真实记录驱动**：概览、复盘与调整只读取已确认记录，没有记录时不出图、不给结论。

## 📋 开发约定与流程

- **文档统一**：项目说明集中在 README、项目介绍与技术文档，避免重复散落的说明文件。

## 🧩 核心功能

### 1. 🍱 餐食记录

- **拍照或上传**：支持相机与相册，上传前压缩到 1024px。
- **双模型识别**：视觉模型识别菜品与份量，结构化模型输出菜名、食材、克数、热量、蛋白质、碳水与脂肪。
- **食物库匹配**：与内置食物参考库匹配，补全每 100g 参考值后按克数换算。
- **区间估算**：结果带误差区间与提示，用户可修改后确认。
- **确认入库**：确认前不写入记录；确认后进入当日统计与每周复盘。
- **失败处理**：识别失败时提示重试或手动录入，不生成占位数据。

### 2. 📅 饮食计划

- **目标计算**：按性别、年龄、身高、体重、活动量与目标计算基础代谢、能量目标、三大营养素与餐次区间。
- **Agent 建议**：在工具白名单内读取餐食汇总、营养目标、天气与指南片段，补充可执行建议。
- **重点标记**：依据餐食汇总信号标记「蛋白质重点」或「份量重点」，至多一项，不修改热量目标。
- **版本管理**：生成结果写入 PlanVersion，新版本默认启用，历史版本可回看、启用、删除。
- **对话修订**：支持多轮意见调整，只描述实际变化，跳过二次 Agent，实测约 4.5 秒。

### 3. 🏃 运动计划与打卡

- **器械适配**：按可用器械、训练天数与单次时长筛选动作并排训练日。
- **逐项打卡**：训练卡逐项勾选，`steps Json` 记录每步完成态。
- **完成记录**：全部步骤完成才写入 `completedAt` 记一次训练；示例与未来日期不可打卡。
- **周复盘同步**：训练完成记录进入每周复盘，与餐食偏差信号一起构成动态调整输入。

### 4. 📊 每周复盘与体重趋势

- **餐食偏差**：按餐次与全天两个维度对照计划区间，超过阈值时给出提示。
- **训练完成**：汇总本周训练次数与完成情况。
- **体重趋势**：同日记录覆盖，单条记录即出图，同值也显示，平线使用局部刻度避免误导。
- **真实记录**：趋势只读取真实记录，没有记录时不画图。

### 5. 💬 健康搭子

- **多会话**：对话按账号隔离，支持新建、切换与删除。
- **流式回答**：SSE 逐字输出，固定高度内滚，支持全屏模式。
- **引用回链**：回答引用知识库片段，绑定标题、来源与序号。
- **语音输入与播报**：Web Speech 入框后可直接编辑，播报逐条朗读、可随时停止。
- **反馈留痕**：点赞与点踩写入 Feedback 表，便于后续优化。
- **浮动头像**：可拖拽，拖动不触发点击，气泡悬停或聚焦时再次显示。

### 6. 🏠 首页概览

- **今日热量与饮水**：热量卡读取真实记录，饮水柱状图按天保存。
- **今日训练卡**：只读已启用计划，分训练、休息、未启用三种状态。
- **九宫格入口**：今日切片可点击跳转，悬停凸起、其余模糊。
- **体重趋势**：展示最近记录与变化方向。
- **减弱动效**：系统开启减少动态效果时全部降级。

### 7. 👤 我的空间

- **健康资料**：维护性别、年龄、身高、体重、活动量、目标、器械与城市。
- **体重录入**：可直接填写并只读同步概览与复盘。
- **资料起点**：资料中的体重作为趋势起点的来源标注。

### 8. 🔐 登录与账户

- **邮箱密码**：注册与登录，密码使用 bcrypt 哈希存储。
- **JWT 会话**：有效期 30 天，会话内统一解析 `userId` 与 `profileId`。
- **免注册体验**：使用 httpOnly 会话 cookie 的沙盒，数据只存在进程内，与账号数据互不读写。
- **生产开关**：`DEMO_MODE="false"` 时关闭演示模式，恢复登录校验。

## 🛠️ 技术架构

### 前端

- **Next.js 16**：App Router、React Server Components、Route Handlers、SSE 流式响应。
- **React 19 + TypeScript 5.9**：全量类型检查。
- **Tailwind CSS 4 + shadcn/ui 结构**：原子化样式、CSS 变量与组件变体。
- **Framer Motion + GSAP**：页面过渡、首页滚动与视差。
- **ECharts 6**：体重趋势与复盘图表。
- **Web Speech API**：语音输入与逐条播报。

### 服务端

- **AI SDK 7**：`streamText`、`generateObject`、`embed` 与工具调用。
- **MCP Client/Server 2.4**：工具注册、调用与 `/api/mcp` 端点。
- **Auth.js 5**：Credentials 登录与 JWT 会话。
- **Zod 4**：请求参数与工具参数校验。
- **23 个 Route Handlers**：覆盖认证、资料、餐食、计划、调整、训练、体重、助手、工具与评测。

### AI 服务

- **对话模型**：DeepSeek flash，关闭思考，首句延迟优先。
- **计划模型**：DeepSeek pro，开启思考，处理多约束规划。
- **视觉模型**：Qwen 视觉模型，负责菜品与份量识别。
- **结构化模型**：DeepSeek flash，把识别描述转为严格 JSON。
- **向量模型**：text-embedding-v4，1024 维（可切换同维 bge-m3）。
- **天气**：Open-Meteo，支持 1–3 天预报。

### 数据存储

- **MySQL 8**：业务数据与知识片段，向量以 JSON 存储。
- **Prisma 7**：模型、迁移与类型安全查询。
- **知识库**：27 篇文档、62 个片段，约 280 字分块，哈希 ID 去重。
- **检索评测**：43 条查询（39 条正向、4 条负向），hybrid 与 vector 的 Hit@3、Hit@5 为 100%，MRR 0.987，平均 23 ms。

### 核心模块

1. `lib/plan-engine.ts`：营养目标与训练排程。
2. `lib/plan-agent.ts`：受约束 Agent 与工具白名单。
3. `lib/plan-adjustment.ts`：偏差评估与临时调整。
4. `lib/rag.ts`：混合检索、重排与 NO_MATCH。
5. `lib/ai-safety.ts`：输入闸门与输出后置校验。
6. `lib/meal-vision.ts`：餐食识别流水线。
7. `lib/mcp-server.ts` / `mcp-client.ts`：MCP 工具与调用。
8. `lib/ai-logger.ts`：请求日志与工具序列。

## 🚀 快速开始

> 提交包不包含 `node_modules/`、`.next/` 与 `.env.local`，首次运行需要安装依赖并生成本地配置。

### 1. 环境准备

- Node.js 24
- MySQL 8（本机安装或可访问的实例）
- 可选：OpenAI 兼容的对话/视觉/Embedding 服务与云端 TTS 服务

不配置模型 Key 也可以启动：`DEMO_MODE=true` 时可直接体验演示流程；AI 助手、拍照识别、语音朗读与 RAG 检索需要对应 Key。

### 2. 安装依赖

```bash
npm install
```

### 3. 配置环境变量

```bash
copy .env.example .env.local
```

macOS / Linux 使用：

```bash
cp .env.example .env.local
```

至少填写数据库连接；需要 AI 能力时再补模型配置：

| 变量 | 是否必需 | 用途 |
| --- | --- | --- |
| `DATABASE_URL` | 必需 | MySQL 连接串，例如 `mysql://user:password@127.0.0.1:3306/zhiyang` |
| `AUTH_SECRET` | 生产必需 | 登录会话签名；本地开发与演示模式有兜底值 |
| `OPENAI_*` | AI 功能需要 | 对话、计划生成与修订的模型服务 |
| `VISION_*`、`MEAL_*` | 餐食识别需要 | 图片识别与结构化分析 |
| `EMBEDDING_*` | RAG 检索需要 | 知识库向量化与检索 |
| `TTS_*` | 云端朗读需要 | 百炼 Qwen-TTS；留空时复用 `EMBEDDING_API_KEY` |
| `DEMO_MODE` | 可选 | 默认 `true`；生产环境设为 `false` 恢复登录校验 |

`.env.local` 只保存在本机，已被 `.gitignore` 排除，不要提交到仓库或发给评委。

### 4. 初始化数据库

```bash
npm run db:setup
npm run db:generate
```

`db:setup` 会自动创建 `DATABASE_URL` 指定的数据库（如果不存在）并建表，需要 MySQL 账号具备建库、建表权限。需要知识库检索时，再执行：

```bash
npm run rag:ingest
```

该步骤需要 `EMBEDDING_API_KEY`。

### 5. 启动

```bash
npm run dev
```

浏览器打开 http://localhost:3000。

Windows 也可以双击 `启动智养AI.bat`：首次运行缺少 `.env.local` 时，脚本会用 `.env.example` 生成并打开记事本，填好 `DATABASE_URL` 保存后再次双击即可；该脚本默认使用 3100 端口，启动后打开 http://localhost:3100。macOS / Linux 或需要指定端口时运行：

```bash
npm run dev -- -p 3100
```

首次启动会生成 `.next` 缓存，之后启动会快很多。

### 6. 质量检查

```bash
npm run typecheck
npm run lint
npm run build
```

### 7. 常见问题

- 页面打不开：确认终端已出现 `Ready`，并检查端口是否被占用。
- 页面能打开但 AI 报错：检查 `OPENAI_*`、`VISION_*`、`EMBEDDING_*` 是否已配置。
- 登录或计划保存失败：确认 MySQL 正在运行，`DATABASE_URL` 的账号能访问对应数据库。
- 首次启动很慢：属于正常安装与编译；`node_modules` 与 `.next` 不随提交包分发。



## 💡 使用指南

### 餐食记录

1. 进入餐食记录，拍照或选择图片。
2. 等待识别与营养估算，检查菜品、克数与区间。
3. 修改不准确的项，确认后按餐次入库。
4. 在首页热量卡与周复盘查看真实记录。

### 计划生成与修订

1. 在「我的空间」补全资料、目标与训练条件。
2. 生成计划，查看营养目标、餐次安排与训练排程。
3. 对计划有意见时直接对话修订，生成新版本。
4. 在版本历史中启用、回看或删除旧版本。

### 训练与复盘

1. 按计划完成训练，逐项勾选步骤。
2. 全部步骤完成后记一次训练。
3. 在每周复盘查看训练完成、餐食偏差与体重趋势。
4. 单餐或全天热量超过阈值时，按提示确认临时调整。

### 健康搭子

1. 打开健康搭子，选择或新建会话。
2. 输入问题或使用语音输入。
3. 查看回答与引用来源，可回链到知识片段。
4. 需要朗读时开启逐条播报。

### 我的空间

1. 填写资料、目标、器械与城市。
2. 录入体重，查看概览与复盘同步。
3. 资料体重会作为趋势起点的来源标注。

## 🔒 隐私与安全

- **账号隔离**：所有查询按 `userId` / `profileId` 限定，数据不跨账号。
- **密码保护**：bcrypt 哈希存储，登录后签发 30 天 JWT 会话。
- **密钥管理**：模型与数据库密钥只通过环境变量注入，不写入源码与仓库。
- **免注册沙盒**：演示数据保存在服务端进程内，按会话隔离，重启即清空，与账号数据互不读写。
- **输出安全**：输入闸门与输出后置校验覆盖自伤、用药、诊断与就医淡化四类风险。
- **日志边界**：请求日志只记录模型、耗时、工具序列、安全标记与字数，不保存提示词全文。
